# memory/ — 项目记忆库

本目录保存**项目的长期记忆**：为什么做某个决定、调研到了什么、现在停在哪。任何一次会话结束时，本目录必须能独立回答"这个项目做过哪些决定、依据是什么、还有哪些悬而未决"。

## 文件职责

| 文件 | 职责 | 更新时机 |
|---|---|---|
| `STATE.md` | 当前状态快照：阶段、已完成、进行中、下一步、阻塞 | **每次会话结束前必更新** |
| `OPEN.md` | 待决问题清单（Qnnn），需用户/外部条件才能推进的事项 | 有新问题时追加；解决后标记并移到决策记录 |
| `decisions/Dnnn-*.md` | 架构决策记录（ADR），一个决策一个文件 | 做出决策时立即写 |
| `findings/Fnnn-*.md` | 调研结论：查到的客观数据、源码分析结果 | 调研完成时写 |

**会话起手顺序**：`STATE.md` → `OPEN.md` → 相关 `decisions/`。
**会话收尾顺序**：写 `decisions/`（若有新决策）→ 更新 `STATE.md` → 更新 `OPEN.md`。

## 决策记录（ADR）模板

```markdown
# Dnnn — <一句话标题>

- **状态**：提议 / 已定 / 待定 / 已放弃 / 被 Dnnn 取代
- **日期**：YYYY-MM-DD
- **决策者**：用户 / PI-Desktop（提案，用户确认）

## 背景
为什么现在必须做这个决定；受哪些硬约束。

## 决策
具体做了什么选择（可执行、可检验的表述）。

## 理由
支撑该选择的事实与推理。区分"已验证事实"与"判断"。

## 备选方案与否决理由

## 影响与后续
需要随之改变的东西；后续需要复核的触发条件。
```

## 编号与状态规则

- 编号 `Dnnn` / `Fnnn` / `Qnnn` **不复用**，作废的保留文件并标 `已放弃`。
- 决策被推翻时：新建一条决策，在旧文件状态写 `被 Dnnn 取代`，**不要改写历史**。
- 事实必须可追溯：调研类结论要写清数据来源（仓库名、分支、提交时间、命令或 API 路径）。

## 事实与判断的分界

记录时必须区分：

- **已验证**：亲自执行命令/查询得到的（例如"`crdroidandroid/android_kernel_xiaomi_sm8150@17.0` 的 `Makefile` 为 4.14.357"）。
- **判断**：基于经验的推测（例如"相机栈在 6.18 上大概率无法闭环"），需标注"判断，未验证"。
