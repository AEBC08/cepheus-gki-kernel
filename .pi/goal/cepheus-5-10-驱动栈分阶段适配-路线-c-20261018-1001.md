# 目标：在 ACK android12-5.10 上完成 cepheus（SM8150）驱动栈的分阶段适配

## Goal

沿用已拍板的 **路线 C**（D013/D014）：以 ACK `android12-5.10` 为内核核心、公开 CAF techpack 为 vendor 驱动来源、SM8150 平台代码从 5.4 前移树移植。

按批次推进（B1a → B1 → B2 → B3 → B4），**每一批都以真实的 CI 构建证据收口**，并把决策、实测结果、风险同步写入 `memory/` 与 `docs/`。最终产出一份「驱动栈接入完成、可进入真机验证」的 `Image` + `cepheus-sm8150.dtb`，同时保持 5.4 参照基线（`kernel-5.4-baseline`）随时可复现。

不追求"一次做完"：批次失败时按实测错误迭代，必要时记录方案变更。

## 现状基线（已具备）

- 仓库 `AEBC08/cepheus-gki-kernel`（公开），HEAD `10efcc6`，28 个提交，工作区干净
- 已打通：`Image`（29.9 MB）+ `cepheus-sm8150.dtb`（DTS 告警 31→2）、overlay+patch 改动机制、5.4 基线复现（27 分 28 秒）
- 已量化：SM8150 平台专用非 DT 文件 **31 个**；B1 时钟批次的缺口是 CAF clk 框架扩展（`vdd-level.h`、Trion PLL）
- 已有决策 D001–D015、发现 F001–F012

## Acceptance criteria

每个批次（B1a、B1、B2、B3、B4）都必须同时满足下列 1–4 条，才算完成：

1. **构建证据**：`kernel-build` 的一次 run（注明 run 编号）中，「构建」步骤 conclusion = success，且 artifact 内含 `Image`（≥ 20 MB）与 `kernel.config`。
2. **配置断言**：该批次对应驱动的 `CONFIG_*=y` 在 `kernel.config` 中存在（逐项列出并核对）。
3. **符号断言**：`System.map` 中至少出现该批次驱动的一个符号（grep 计数 ≥ 1），证明确实编进了内核，而非仅开关打开。
4. **记录完整**：对应 `memory/findings/F0xx`（含实测数据、run 编号、错误量化）已写入；必要时新增 `memory/decisions/D0xx`；`memory/STATE.md`、`memory/OPEN.md`、`docs/risk-register.md` 同步更新；本地与远端 HEAD 一致。

批次专项验收：

5. **B1a**：CAF clk 框架扩展（`vdd-level.h`、`clk-alpha-pll.c/h`）已导入并在 D015 名册登记；构建日志 `error:` 计数为 **0**。
6. **B1**：`camcc/dispcc/npucc/scc-sm8150` 四个驱动均满足 1–3 条。
7. **B2/B3**：pinctrl、interconnect、LLCC 三批各自满足 1–3 条（若某子系统判定无需移植，须给出 of_match 对照证据并记为"复用上游"）。
8. **B4**：`techpack/display` 由构建流程引入并参与编译（有 `.o` 产出或 System.map 符号），构建通过；若判定 5.10 分支与 ACK 核心不兼容，须给出量化证据与替代方案决策，而不是无限期挂起。

全流程约束：

9. **既有能力不回退**：`kernel-5.4-baseline` 可再次触发成功并产出 artifact；`kernel-build` 默认目标 `Image dtbs` 仍 success；DTS 告警数 ≤ 2。
10. **真实性**：所有结论必须来自实际 CI 运行的日志/artifact（附 run 编号）；不得出现未执行却声称完成的项目。
11. **工程规范**：提交信息符合 D005；`overlay`/`patch` 遵守 D010；框架级覆盖仅限 D015 名册且每次登记理由与影响面。

## Boundaries

1. **不做真机操作**：不刷机、不进 EDL/fastboot 写分区。实机验证必须由用户明确指令后才执行。
2. **源码不入库**：不提交内核源码树或 >10 MB 的二进制；源码仍由 CI 拉取（D008）。
3. **不改写历史**：不使用 force-push、不修改已推送提交、不改动用户仓库中的其它内容。
4. **不越界覆盖**：除 D015 名册登记的框架文件外，不整文件覆盖 ACK 上游文件；差异必须能用 patch 表达。
5. **凭据安全**：仅使用本机 Git Credential Manager 的缓存凭据；不把 token 写入文件、remote URL 或日志。
6. **遇阻即停**：单批次编译错误数 > 100 处，或需要变更基线/技术路线（例如放弃 GKI 2.0 形态）时，暂停并提交方案，不硬推。
7. **不做无关改动**：不重构、不格式化与机型适配无关的代码。
8. **配额意识**：CI 构建是有成本的操作，避免无意义的重复触发；每次构建应针对一个明确的验证点。

## 完成定义（Definition of Done）

B1a–B4 全部满足各自验收条款，且 `STATE.md` 中的"下一步"只剩「真机验证」时，本目标视为完成；此时向用户提交一份汇总报告：各批次 run 编号、产物清单、尚未解决的风险（如 camera/audio 的 tag 选型）。
